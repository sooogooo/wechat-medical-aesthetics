# 全站深度优化方案

> 基线：2026-08-16 实测。175 个静态页（门户 + 皮肤 55 + 手术 31 + 注射 41 + 亚美学 10 + 三型 10 + 成长站 23 + 声明/404），总体积 1.6MB，零框架零外部依赖，系统字体栈。
> 结论先行：**性能已经是静态站的理论最优区**（最大单文件 32KB），深度优化的主战场在 SEO/分享基建、全站可发现性、学习体验闭环、工程质量四条线，不在加载速度。

---

## 一、现状基线（本次实测）

| 维度 | 现状 | 评价 |
| --- | --- | --- |
| 页面/体积 | 175 页 HTML，全站 1.6MB | 优 |
| 死链/占位链接 | 4324 个站内链接，零死链零占位 | 优（有自动检查器） |
| SEO 基建 | robots.txt ✕、sitemap.xml ✕、canonical 0/175、JSON-LD 结构化数据 0 | **空白，最大短板** |
| 分享卡（og:image） | 成长站 22/23，科普系列 0/86，且 og:image 为 SVG 相对路径 | 弱：微信/社交抓取不可靠 |
| 全站搜索 | 无（各系列列表页有单系列过滤） | 空白 |
| 数据原料 | assets/data/ 已有 6 个 JSON 索引（课程+五系列，共 ~100KB） | 搜索可零成本搭建 |
| 学习交互 | 课文页有进度条/键盘翻课/任务打勾（localStorage，22 页） | 有地基，未成系统 |
| 移动端/溢出 | 27 场景矩阵全绿，390px 无横向溢出 | 优 |
| 构建 | 三个构建器 + 5 个检查脚本，命令分散 | 可整合 |

## 二、方向 A：SEO 与分享基建（P0，上线前必做）

### A1 robots.txt + sitemap.xml
- 做法：构建器扫描全部 HTML 生成 `sitemap.xml`（含 lastmod）；`robots.txt` 放行并指向 sitemap
- 验收：sitemap 覆盖 175 页；W3C 校验通过；robots 可访问
- 工作量：S（半小时）

### A2 canonical 与 meta 全覆盖
- 做法：三个构建器统一输出 `rel="canonical"`（相对 → 部署时按域名绝对化，见 F2）；科普 86 页补 og:title/description/image
- 验收：175/175 页有 canonical；og 三件套全站覆盖
- 工作量：S

### A3 分享卡 PNG 化 + og:image 绝对地址
- 现状：og:image 是 SVG 相对路径，微信/QQ/微博抓取基本忽略
- 做法：①用无头浏览器或部署后线上工具把每系列首页+课程首页截 1200×630 PNG（或按系列做 6 张统一模板卡）；②og:image 改为域名绝对 URL
- 验收：微信发送链接出现标题+摘要+缩略图
- 工作量：M（依赖域名确定）

### A4 结构化数据（JSON-LD）
- 做法：科普文章页注入 `Article`（含 datePublished、headline、description）；课程页注入 `Course`+`CourseList`（含教育层级、_provider 医院名）；门户注入 `WebSite`+SearchAction（配合 B 站内搜索）
- 验收：Google Rich Results Test 通过；搜索结果出现课程富摘要
- 工作量：M

### A5 中文 SEO 细节
- 每篇 h1 已含长尾词（体检时确认）；补 `<html lang>` ✓ 已有；列表页补 prev/next rel；历史页面 noindex 判断（无）
- 工作量：S

## 三、方向 B：可发现性——全站搜索与互链网（P0-P1）

### B1 全站搜索页（`/search.html`，纯客户端）
- 现状原料：6 个 JSON 索引已含 title/summary/keywords，~100KB，加载后本地检索零后端
- 做法：新建搜索页，拉取合并 6 个 JSON，标题+摘要+关键词中文分词（简易 bigram 匹配即可），结果按系列分组并带系列色标；门户 header 加搜索入口；`WebSite SearchAction` 指向它（A4）
- 验收：搜"玻尿酸"返回注射系列+课程第 07 课；搜"红绿灯"返回成长站；首屏可交互 < 300ms（本地索引）
- 工作量：M（半天）

### B2 科普 ↔ 课程互链网
- 现状：课程 → 科普是单向链接（59 处）；科普文章不知道自己被哪课引用
- 做法：构建时反向扫描课程 md 的教材链接，在科普文章页"相关学习"区块输出"本篇是《一路绿灯》第 N 课精读教材"；门户各系列卡片补"配套课程"链接
- 验收：抽查痤疮页出现"第 06 课精读教材"回链；链接检查器通过
- 工作量：M

### B3 系列内导航增强
- 文章页底部加"本系列上一篇/下一篇"（数据在各自 JSON 里，构建时注入）
- 验收：任意科普文章可键盘中 ←/→ 翻篇（与成长站课文一致）
- 工作量：S-M

## 四、方向 C：学习体验闭环（P1）

### C1 课程进度系统（把散落的 localStorage 变成产品）
- 现状：仅第 20 课任务清单有本地存储；无"已读"概念
- 做法：①每课页尾加"标记本课完成"按钮，写 localStorage；②首页旅程图与阶段卡读进度，已完成的课程卡点亮绿灯、阶段节点显示 n/20；③第 20 课结业自检全部勾选后解锁"结业卡"页（本地渲染：姓名+日期+五盏绿灯，可打印/截图）
- 验收：完成 3 课刷新首页，对应卡片点亮；结业卡在完成 20/20 后可打开
- 工作量：M

### C2 打印样式（课件纸用）
- 做法：`@media print` 隐藏页头/分享/灯箱/进度条，正文全宽、图表分页避免截断、作业区加边框；路径 `_print` 无需，直接响应打印
- 验收：浏览器打印预览 20 课每课 ≤6 页、图不截断
- 工作量：S

### C3 阅读辅助
- 正文字号三档调节（小/中/大，localStorage 记忆，尊重系统偏好）；长课文顶部浮动小节目录（现有五分区锚点）
- 验收：字号切换持久化；目录滚动高亮当前节
- 工作量：S-M

### C4 移动端手势细节
- 课文页左右边缘滑动翻课（与桌面 ←/→ 对齐）；灯箱已有双指/双击
- 验收：390px 实机边缘滑动翻页，不与横向滚动冲突
- 工作量：M（需防误触）

## 五、方向 D：性能与可访问性精修（P1-P2）

性能现状已近上限（1.6MB/175 页，无阻塞资源），仅做精修：

- **D1 CLS 归零**：科普文章 hero 图与课程 figure 统一声明 `width/height`（SVG 已有内在尺寸，补 img 属性与 CSS aspect-ratio 兜底）。验收：Lighthouse CLS < 0.02
- **D2 首屏预载**：门户与课程首页 `<link rel="preload">` 首屏 SVG 卡图（仅 2-3 张）；其余维持 lazy。验收：LCP < 1.2s（本地）
- **D3 可访问性收尾**：全站 skip-link（跳到正文）；焦点环统一 2px 阶段色；`figure` 补 `role`/长 desc；色彩对比复核（ink-faint 在小字场景达到 4.5:1）。验收：axe 扫描零 critical
- **D4 Lighthouse 门槛入 CI**：四个维度 ≥95 作为验收门禁（本地跑）
- 工作量：合计 M

## 六、方向 E：工程质量与构建统一（P1）

- **E1 一键构建与校验**：新增 `build-all.js` 串起 3 个构建器 + 标点清洗 + 4 个检查器（链接/SVG 良构/图表门禁/溢出静态扫），`npm run build` / `npm run verify` 两条命令走天下；产物与源不再有"改了源忘重建"的窗口（本次 skin 目录就发生过）
- **E2 缓存破坏**：CSS/JS 引用加内容 hash 版本号（`consultant.css?v=abc123`），构建时注入；SVG 图名已含语义版本可不动
- **E3 数据一致性**：`consultant.json` 等索引由构建器产出 ✓，把"series tagline/阶段数据"收拢进单一 config，消除 README/总纲/构建器三处重复维护
- **E4 交付物**：`verify` 通过后自动重打部署 zip（沿用 bsdtar 方案+完整性自检）
- 验收：`npm run verify` 全绿一条命令；zip 产物字节校验自动通过
- 工作量：M

---

## 七、方向 F：部署与运维（P0 交付期）

- **F1 静态服务器配置样例**（随仓库提交 `deploy/nginx.conf`）：gzip/brotli 开启（文本资源压至 ~35%）；`assets/` 与图片缓存 30 天 + immutable（配合 E2 hash）；HTML 不缓存或短缓存；404 → /404.html；UTF-8 charset；可选 CORS 允许 og 抓取
- **F2 域名确定后的绝对化**：构建器加 `--base https://<域名>` 参数，一次性把 canonical、og:image、sitemap loc 全部绝对化（当前均为相对路径，子路径部署友好但社交分享需绝对）
- **F3 可观测（轻量、无隐私负担）**：若需访问数据，接自托管 Umami/Plausible 或服务端日志统计即可，不放第三方跟踪脚本（医疗内容站谨慎）
- **F4 更新流程固化**：改 md → `npm run build` → `npm run verify` → zip → 上传（写入 README 一行命令说明）
- 工作量：S-M

## 九、明确不做（与定位冲突）

- 不加评论/账号系统（静态站定位，医疗内容开放评论有审核负担）
- 不做夜间模式（医疗科普以清晰阅读为先，暖白纸面是设计决策）
- 不引入前端框架/分析SDK（175 页零依赖是当前最大架构资产）
- 不为 SEO 堆砌关键词页（内容质量与真实性优先，符合声明页的实验定位）
